# LeakLens — Claims Leakage Detection Agent

An AI-powered claims validation application for insurers: it ingests claims, invoice lines, policy terms and claim
history (CSV / Excel / JSON) or scanned claim documents, checks every claim line against the policy, finds duplicates
and settlement errors, puts a rupee/dirham amount on each finding with the rule and the evidence, and lets a claims
handler confirm, correct or dismiss each finding before settlement.

**AI finds and explains; rules compute every amount; humans decide.**

Read `docs/PLAN.md` first: the brief, the architecture, the API contract, the screens and who builds what.

## Layout

| Folder | What |
|---|---|
| `core/` | the engine: `schemas/` (master dataset, Finding, Settlement), `checks/` (the leakage checks), `prompts/` (versioned model prompts), `llm/` (model client: Bedrock, retries, schema validation, cost cap, cache), `media/` (page images), `engines/` (bill helpers) |
| `backend/` | FastAPI API, store (MongoDB or local JSON), LangGraph workflow with human review gates, audit log |
| `ui/` | React review console |
| `data/synthetic/` | the synthetic dataset generator and its output (no real people, providers or insurers) |
| `data/policies/` | policy wordings with numbered clauses (synthetic insurers) |
| `eval/` | scoring against the hidden answer key |

## Run

```bash
python -m venv .venv && .venv/Scripts/pip install -r core/requirements.txt -r backend/requirements.txt
cp .env.example .env            # add your AWS Bedrock keys (ap-south-1)
python -m data.synthetic.generate --out data/synthetic/out
uvicorn backend.main:app --reload --port 8000     # API + /docs
cd ui && npm install && npm run dev               # review console
```

## Models

Kimi K2.5 on AWS Bedrock (primary) and Claude Sonnet on Bedrock (fallback) through litellm; Titan Text Embeddings v2
for policy-clause retrieval. Every model answer is validated against a Pydantic schema; money is never computed by a model.

## Data

Synthetic only. Names, providers, insurers, policy numbers and amounts are generated by `data/synthetic/generate.py`
from a fixed seed. No customer or production data is used anywhere.

## Reuse

Prompt templates and a few bill-parsing helpers under `core/` were adapted from the team's prior work, with permission.
Everything else was written during the event.
